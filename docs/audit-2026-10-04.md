## Подробности

### H1. Успешная заявка заканчивалась сообщением «ассистент недоступен»

- Где: `chat-api/src/chat.ts`, `chat-api/src/http.ts`.
- Почему: после отправки заявки следующий вызов модели шёл без `tools`, а в
  истории уже были блоки `tool_use`/`tool_result`. Messages API такой запрос
  отклоняет (400 «Requests which include `tool_use` or `tool_result` blocks
  must define tools»). Обработчик возвращал запасной ответ с
  `requestSent: false`. Итог: Карина получала заявку, посетитель видел
  «ассистент недоступен», повтор отправлял дубликат. Тесты этого не ловили:
  модель в них подменена фейком, который принимал любые параметры.
- Сделано: `tools` передаются в каждом вызове, после отправки — с
  `tool_choice: {type: "none"}`. Если ответ после отправки не удался,
  посетитель получает подтверждение `FALLBACK.sent` с `requestSent: true`.
  Фейк в тестах теперь отклоняет такие запросы, как настоящий API.

### H2. API по умолчанию был открыт для скриптов

- Где: `chat-api/src/http.ts`, `index.ts`, `chat.ts`, `config.ts`,
  `turnstile.ts`, `infra/azure/setup-chat.sh`.
- Почему: Turnstile был выключен, пока его не настроят; заголовок `Origin`
  подделывается; лимит по IP брал левую запись `X-Forwarded-For`, которую
  задаёт клиент; правило «одна заявка на разговор» доверяло флагу браузера.
  Один скрипт мог отправить около 500 фейковых заявок в день в Telegram и на
  почту Карины, в том числе с чужими телефонами.
- Сделано:
  - Turnstile обязателен: без секрета API отклоняет сообщения (отключается
    только настройкой `HUMAN_CHECK=off`). `/api/health` показывает
    `humanCheck: on | missing | off`.
  - Общие лимиты в Table Storage: не больше 20 заявок в день
    (`DAILY_REQUEST_LIMIT`) и одна заявка на номер телефона в сутки (UTC).
  - Лимит по IP берёт правую запись `X-Forwarded-For` (её добавляет платформа).
  - Тело запроса больше 256 КБ отклоняется (413).

### H3. Turnstile в виджете не работал

- Где: `components/chat/chat-widget.tsx`.
- Почему: `size: "invisible"` — недопустимое значение (только normal,
  flexible, compact). Виджет рендерился в элемент панели, который исчезал при
  закрытии, а ссылка на виджет оставалась: после повторного открытия каждое
  сообщение ждало 15 секунд и получало 403.
- Сделано: `size: "compact"` (помещается в панель на телефоне 320 px),
  `appearance: "interaction-only"` (виджет виден, только если Cloudflare
  просит посетителя что-то сделать), виджет удаляется при закрытии и создаётся
  заново при открытии, первое сообщение ждёт загрузки проверки. Рекомендуется
  режим Managed: режим Invisible по правилам Cloudflare требует политику
  конфиденциальности со ссылкой на их Turnstile Privacy Addendum. Добавлен
  E2E-тест с фейковым Turnstile (закрыть → открыть → отправить снова).

### M6. Заявка, которая никуда не дошла, считалась отправленной

- Где: `chat-api/src/chat.ts`.
- Почему: сохранённая строка в таблице считалась успехом, даже если Telegram и
  почта не сработали или не настроены. Таблицу никто не читает. Живая проверка
  `/api/health` этого не видит: почта в Bicep «настроена» всегда.
- Сделано: заявка считается отправленной, только если её доставил хотя бы один
  канал. Иначе посетителю предлагают WhatsApp или звонок, пишется лог уровня
  error, номер освобождается для повторной попытки. Строка в таблице
  сохраняется как запись.

### M1. Мощность Claude 10 тыс. токенов в минуту

- Где: `infra/azure/chat.bicep` (Microsoft считает capacity в тысячах TPM).
- Почему: ход с заявкой занимает около 5 тыс. токенов; 2–3 одновременных
  посетителя получали бы 429.
- Сделано: 50 (квота pay-as-you-go для Haiku 4.5 — 80 тыс. входных TPM;
  мощность оплачивается только по использованным токенам).

### M2. Текст о приватности (открыто)

В чате написано «Ваши контакты получит только студия», но сообщения
обрабатывает Claude в Microsoft Foundry, а заявки хранятся в Table Storage
бессрочно. Политики конфиденциальности нет. Нужны: точная формулировка (EN и
RU), короткая политика (с упоминанием Cloudflare Turnstile), срок хранения
заявок. Формулировку должен утвердить владелец.

### M3. Свой домен молча сломал бы чат

- Почему: `SITE_URL` описан как единственный переключатель домена, но API
  пропускает только `https://ka-nails.pages.dev`.
- Сделано: `setup-chat.sh` спрашивает разрешённые адреса сайта; README и
  `CLAUDE.md` говорят обновлять `ALLOWED_ORIGINS` вместе с `SITE_URL`;
  `verify-live` проверяет, что CORS preflight с адреса сайта даёт 204.

### M4. Устаревший E2E-тест реальной записи

`tests/site.spec.ts` нажимал ссылку «Explore services», которой больше нет.
Тест здесь пропускается, поэтому поломку не было видно; харнесс GORGONA упал
бы при включении записи. Теперь тест идёт через «Book an appointment» в
главной навигации.

### M5. Артефакт для ручной загрузки (открыто)

`ka-nails-out-<sha>` собирается без `SITE_INDEXING`, `SITE_URL`,
`CHAT_API_URL`, `TURNSTILE_SITE_KEY`. Пока задан токен Cloudflare, путь не
используется; при ручной загрузке опубликовался бы другой сайт.

### Низкая важность

- L1: префикс промпта (~1,5 тыс. токенов) меньше минимума кэша Haiku 4.5 (4096),
  так что `cache_control` не действует. Вреда нет.
- L2 (исправлено): проверка «не больше двух знаков после точки» ломалась на
  float (19.99 × 100 = 1998.9999999999998); теперь с допуском.
- L3: `tools/generate-gallery-assets.mjs` пишет синтетические SVG в
  `public/gallery`; 36 фикстур с текстом «manicured»; 14 из 20 скриптов в
  `tools/` нигде не используются (эпоха Studio.Design).
- L4: «Carefully sanitized implements» не подтверждено владельцем; устаревшие
  мета-описания book и contact; число «19» в 10 строках; «Restorative» может
  читаться как медицинское обещание.
- L5: CI запускается дважды на push в PR; `cancel-in-progress` на `main`;
  предупреждения о Node 20 в actions; теги вместо SHA; нет переменной для
  URL записи.
- L6: доступные имена ссылок EN/RU не содержат видимый текст (WCAG 2.5.3);
  вложенный `<nav>`; кнопка чата может перекрывать элемент в фокусе

- L7: `braces` ≤3.0.3 через `eslint-config-next` — только dev, в сборку не
  попадает; предложенный npm откат делать не надо. В `chat-api` уязвимостей нет.
- L8: в `CLAUDE.md` сказано, что тесты проверяют запрет «Nail Studio»; на деле
  только wordmark.
- L9 (почти исправлено): `setup-chat.sh` глушил ошибки назначения ролей
  (почта могла тихо не работать) и ждал доступа к Key Vault ровно 60 секунд.
  Теперь ошибки видны, а запись ключей повторяется до 5 минут. Открыто: у
  пользователя остаётся роль Key Vault Secrets Officer (нужна повторным
  запускам).
- L10: sandbox iframe записи без `allow-popups` — проверить с оплатой GORGONA.
- L11: `requestAnimationFrame` в «moving wall» работает всё время, пока открыта
  страница.
- L12: `content/README.md` не говорит, что факты студии использует и

## Что сделано хорошо

- Зелёный CI с проверкой живого сайта после каждого деплоя.
- Жёсткие правила закреплены валидацией фактов при сборке и тестами.
- Сильные проверки доступности (axe, reduced motion, размеры целей, интервалы
  текста, ловушка фокуса в лайтбоксе).
- Беспарольная архитектура Azure: managed identity, ссылки на Key Vault,
  отключённые shared key и local auth, деплой через OIDC.
- Ввод инструмента проверяется по меню, есть дневной лимит стоимости, код чата
  хорошо тестируется.
